# 选稿事实验证

本目录是**验证交付物**，不是生产代码的替代品，也不改变生产选稿语义。它回答一个问题：
**校样所引用的那张 PNG，是否真的来自被选中的那个稿本**——即使修订、取消和成品提交
彼此交错。

所有结论都从真实 PNG 字节重新推导，不依赖任务状态字段、版本字段或服务自报摘要：

```
HTTP 选稿（revision / exposure） -> 成品字节
    -> 独立 PNG 解码（签名、CRC、滤波、尺寸）
    -> 独立合成 oracle（仿射求逆、固定 Q/C 细分、even-odd/nonzero、
       线性光预乘合成、半透明 screen 叠色、2x2 覆盖采样）
    -> 校样 / ETag / X-Scene-Digest 交叉核对
```

## 运行

```sh
python3 verify/run.py                          # 全部旅程，约 1 分钟
python3 verify/run.py --journey geometry-reuse
python3 verify/run.py --report verify-report.json
```

需要 Go 工具链（`PRISM_GO` 可指向 `go` 所在目录）。每次运行都真实执行
`go build ./cmd/prismplate`，在临时数据根上启动真实 HTTP 服务，结束时 SIGTERM 关停。
不改动仓库内任何 Go 文件，不导入生产包。

## 四个旅程

| 旅程 | 证明的事实 | 主要证据 |
|---|---|---|
| `delayed-selection` | 提交时冻结的稿本（r1）在版面追加两次修订后仍然出图；通过校样引用同一字节 | 闸门场景占满两个计算名额使任务确定性 `queued`；四轮探针显示 r1 的镂空，且与最新稿逐像素不同（约 6.8k px）；校样 ETag、`X-Scene-Digest` 与字节一致；撤销被 409 拒绝 |
| `geometry-reuse` | 四个稿本各自出图，PNG 与 SVG 都不得复用别的稿本的几何 | 四张 PNG 逐像素等于各自 oracle；四张 SVG 各含自己的孔洞 token、不含其他稿本的；探针见证两两不同；同稿重复渲染字节一致 |
| `cancel-commit` | 取消与提交交错时，成功事实不被改写为取消，取消不发布残图 | 在观察到的提交窗口内发 DELETE，3/3 仍 `succeeded` 且 PNG 逐像素正确；`queued`/`running` 取消不产生成品；同步请求在提交窗口中断后不复活已撤销成品，若已提交则字节仍正确 |
| `strategies` | 三种时序控制方式的可重复性、侵入程度与覆盖成本对比，并用三类注入偏差证明判定有效 | 见下 |

## 时序控制与观察边界

深度插桩会改变被测量的调度与耗时；纯黑盒随机等待又可能长期碰不到提交窗口。本交付
选择**场景成本 + 公开 HTTP 顺序**作为控制面：

| 方式 | 可重复性 | 侵入程度 | 覆盖成本 | 实测 |
|---|---|---|---|---|
| 纯黑盒随机等待 | 低：命中靠运气，且无法区分"窗口内取消"与"取消前已发布" | 无 | 最低 | 8 次盲等中约半数成功，其中多数在 DELETE 到达前已完成发布；0 次可验证窗口 |
| **提交窗口观察（采用）** | 高：`state-*.tmp` 出现即进入提交点，3/3 命中 | 无（只读列目录 + 公开 HTTP） | 一对闸门场景 + 约 8 s 惰性 SVG 准备 | 提交窗口中位数约 4 ms，填充后约 26–36 ms；每次命中都验证 PNG |
| `-race` + 日志插桩 | 高但不可归因：竞态运行时改变调度 | 高（改树副本、额外构建） | 需要额外构建与更慢运行 | 渲染 0.24 s → 3.85 s（约 16×），因此**不用于**不变量证明 |

为什么用闸门场景：两个预算合法的 512×512 场景占满两个计算名额后，新提交的异步任务
**确定性**停在 `queued`，不需要 sleep 猜时序；放行后它按提交时捕获的稿本执行。

为什么用大 SVG：`state-*.tmp` 是原子快照的提交前写盘，10 个约 3.2 MB 的 SVG 只把该
窗口从数毫秒拉宽到数十毫秒，便于在窗口内发出 DELETE。它只是验证脚手架，服务逻辑、
选稿语义、数据格式都没有变；每轮仍从真实 PNG 重新判定。

为什么用 warm keep-alive 连接：新建 TCP 连接本身的耗时会错过毫秒级窗口；复用连接后
DELETE 与观察到的临时文件处于同一毫秒量级。请求仍是公开的 `DELETE /v1/exposures/{id}`。

## 两类独立偏差的判定有效性

`verify/biases.py` 在**树副本**中注入偏差并重新构建真实二进制；先确认偏差确实体现
在 PNG 上，再确认对应旅程会失败。生产目录不被修改。

| 注入偏差 | 观察到的 PNG 证据 | 被哪个旅程拒绝 |
|---|---|---|
| 延迟选稿失效：执行时改读最新稿 | 四轮探针与最新稿 0 处不符、与捕获稿 4 处不符 | `delayed-selection`：`rejects_latest_revision` 断言失败 |
| 错误复用几何：按版面 id 缓存编译结果 | r2 的 PNG 与 r1 逐像素相同，`hole_r2` 仍是墨色而非镂空 | `geometry-reuse`：逐像素 oracle 比较失败 |
| 透明叠色丢失：合成时丢掉层透明度 | 叠色探针 (217,174,197) vs 期望 (217,147,157)，非叠色探针全部正确 | `geometry-reuse`：逐像素比较（说明只看镂空探针不够，逐像素才抓得住叠色偏差） |

前两类正是题面要求的"延迟选稿"和"错误复用几何"；第三类证明判定不是只盯孔洞。

## 最终图片、摘要与校样引用一致

每张被引用的成品都同时核对四件事：

1. **图片**：PNG 签名、CRC、尺寸，逐像素等于独立 oracle；
2. **摘要**：`ETag` 等于字节的 SHA-256；`X-Scene-Digest` 等于所选稿本的摘要；
3. **校样**：`POST /v1/proofs` 打开、`PUT` 通过后，校样引用成品的字节与被测成品完全
   相同，且受 409 撤销保护；
4. **SVG 校样**：复用同一展开几何，含且仅含所选稿本的孔洞坐标。

`If-None-Match` 命中时服务返回 304，因此验证读取的是原始 200 响应字节，而不是缓存视图。

## 限制（明确不宣称）

- **不是视觉正确性证明**：oracle 按公开契约重写，若契约本身有未文档化的意图，oracle
  与实现可能同错。它证明的是"实现与契约一致"，不是"符合设计者脑中的图"。
- **不是跨平台或跨架构结论**：仅在本次 Linux/arm64、Go 1.25 环境验证。
- **提交窗口的宽度依赖宿主 I/O**：填充后窗口约 26–36 ms，但仍是毫秒级；观察到窗口不等于
  证明窗口内每一纳秒的原子性。`cancel-commit` 重复 3 次、`strategies` 再取 5 个样本。
- **闸门场景依赖"两个计算名额"这一已文档化配置**：若并发名额改变，`await_state` 会失败
  而不是静默跳过，这是有意的。
- **盲等对照是采样而非证明**：8 次样本说明盲等不可靠，不构成统计显著性结论。
- **`-race` 对照只用于比较开销**，不产生任何不变量结论。
- **不覆盖**：多次进程重启后的选稿、跨主机时钟、故障注入、压力/容量耗尽、恶意篡改。
- 生产选稿语义、持久化格式、HTTP 契约均未改变；本目录不参与 `go build ./...`。
